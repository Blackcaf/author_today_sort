# strict_tag_search - строгий поиск книг на author.today

**Строгий групповой поиск** по тегам: ищем книги одновременно по нескольким группам тегов,
собираем результаты со всех страниц, убираем дубликаты и выводим финальный список
с прямыми ссылками. Больше не нужно вручную перебирать десятки страниц в браузере.

Скрипт написан на чистом Python + `requests` и парсит HTML автор.тудея
напрямую.

---

## Зачем это нужно? 

Встроенный поиск author.today - это **одно поле** и одна тема за раз.
Он не умеет:

- искать книги, в которых **сразу есть несколько групп тегов** (AND нескольких групп);
- объединять в одной группе **варианты написания** одного и того же тега (OR);
- показывать **полный список результатов** (поиск по релевантности «плавает» между страницами,
  часть книг теряется по пути).

Этот скрипт закрывает все три пробела:

- каждая группа тегов из вариантов через запятую = **OR**;
- агрументы (группы) обязательны одновременно = **AND**;
- скрипт листает до **200 страниц** по умолчанию, собирает все уникальные работы,
  а затем выводит число результатов как на сайте и сравнивает с фактически собранным.

## Возможности 

- **Групповой поиск с логикой OR/AND** - теги внутри группы через `,`, группы разделяются пробелами.
- **Только завершённые электронные книги** по умолчанию; аудиокниги и незаконченное -
  по флагу.
- **Дедупликация** - один и тот же id работы не выводится дважды (как на страницах).
- **Сверка с числом на сайте** - если страница перемести книги, скрипт честно
  предупредит о расхождении.
- **Авторизация тремя способами**: логин/пароль, куки строкой из браузера, файл
  `cookies.txt` в формате Netscape/curl (самый надёжный путь).
- **Повторы при ошибках** сети (до 3 попыток с паузой), пауза между запросами,
  лимит страниц - чтобы не триггерить защиту от ботов.
- **Быстрый старт** - `pip install requests` и вперёд.

## Использование

```bash
python strict_tag_search.py "игровая система, система" "марвел, dc" [--опции]
```

### Как читать аргументы-теги

- **Внутри одной группы** - это **варианты** одного и того же тега, разделённые `,`.
  Плюс: если книга не находится по одному написанию тега - найдётся по другому.
  Логика: `OR`.
- **Целый аргумент** - отдельная группа. **Все группы обязательны** одновременно.
  Логика: `AND`.

Пример: книга должна быть **одновременно** про систему и про Марвел или DC.

> Если нужно фильтровать по **одному** тегу без вариантов - просто передайте его одним
> аргументом: `python strict_tag_search.py "фэнтези"`.

## Опции (CLI)

| Флаг | По умолчанию | Что делает                                                                                         |
|------|--------------|----------------------------------------------------------------------------------------------------|
| `tags` | — | Один или несколько аргументов-групп с тегами (обязательный параметр)                               |
| `--max-pages N` | `200` | Максимум страниц на один запрос. Упрётся сам по пагинации сайта, лимит — страховка от зацикливания |
| `--delay SEC` | `0.3` | Пауза между HTTP-запросами в секундах (вежливость к сайту)                                         |
| `--any-state` | выкл | Не фильтровать по статусу — включать и **незавершённые** работы                                    |
| `--with-audio` | выкл | Включать **аудиокниги** в результаты (по умолчанию только электронные книги)                       |
| `--email` | — | Email/логин аккаунта author.today для входа                                                        |
| `--password` | — | Пароль (требует `--email`)                                                                         |
| `--cookie` | — | Куки из браузера одной строкой: `"name=value; name2=value2"`                                       |
| `--cookies-file PATH` | — | Путь к `cookies.txt` (формат **Netscape/curl**, экспорт из расширения браузера https://chromewebstore.google.com/detail/get-cookiestxt-locally/cclelndahbckbenkjhflpdbgdldlbecc?hl=ru&utm_source=ext_sidebar)                   |

### Примеры

```bash
# Просто поиск по одному тегу
python strict_tag_search.py "попаданцы"

# Групповой поиск: гарем + Марвел (варианты написания в каждой группе)
python strict_tag_search.py "гарем, гаремник" "марвел 11, марвел11"

# И то же самое + аудиокниги и незавершённые
python strict_tag_search.py "гарем, гаремник" "марвел, марвел 11" --with-audio --any-state

# С куки из браузера (надёжный способ авторизации)
python strict_tag_search.py "детектив" --cookie "_identity=abc...; _session_id=xyz..."

# С файлом cookies.txt в формате Netscape/curl
python strict_tag_search.py "литрпг" --cookies-file "cookies.txt"

# Вход email/паролем
python strict_tag_search.py "хоррор" --email me@example.com --password S3cret
```

## Авторизация

Для поиска логин не обязателен - сайт отдаёт результаты и анонимам, но результатов выдает меньше.
Но авторизоваться можно:

1. **через файл cookies** (самый надёжный): войдите в аккаунт в браузере,
   экспортируйте куки через расширение, например *Get cookies.txt LOCALLY*, затем:
   `--cookies-file "cookies.txt"`. Файл будет содержать строки формата
   `domain  includeSubdomains  path  secure  expiry  name  value` — скрипт разберёт его сам.
2. **строкой куки** из панели разработчика (вкладка *Application → Cookies*):
   `--cookie "_identity=abc...; _session=xyz..."`.
3. **логин/пароль** - скрипт сам возьмёт CSRF-токен и войдёт (`--email` + `--password`).
   Если у аккаунта включена **двухфакторная авторизация (2FA)** — войти скриптом
   не получится, используйте cookie-способы.

После запуска с любым способом аутентификации скрипт проверит, «залогинены ли мы»,
и выведет предупреждение, если сессия не активна (тогда поиск пойдёт как у анонима).

## Что скрипт выводит 

В **stderr**:
- по каждой группе: `Группа N: <теги>`, число результатов с сайта и сколько собрано уникальных;
- предупреждения о достижении `--max-pages` и о расхождении с числом сайта.

В **stdout** (полезные данные):
- итоговое число работ: либо «как на сайте» + собранных уникальных (с пометкой о расхождении ★),
  либо число книг, удовлетворяющих **всем** группам;
- затем список: `  - <название>  https://author.today/work/<id>` (или `/audiobook/<id>`).

Пример вывода:

```
Группа 1: гарем | гаремник
  Ищу одним запросом со всеми тегами группы...
  Результатов на сайте: 1234 (собрано: 1231)
Группа 2: марвел 11 | марвел,марвел 11

Результатов по запросу (как на сайте): 123 (собрано уникальных: 121)
  [!] Расхождение (-2) — сортировка по релевантности сдвигает список между страницами.
  - Гаремный День Марвела  https://author.today/work/12345
  - ...
```

Полезный паттерн: сохранить список ссылок в файл

```bash
python strict_tag_search.py "фэнтези" > result.txt
```

## Осторожно при скаппинге

- Добавляйте `--delay` побольше при больших списках страниц, чтобы не нагружать сайт.
- Не гоните тысячи запросов за минуту - автор.today может забанить IP.
- Скрипт повторяет неудачный запрос 3 раза с паузой 1.5 с, но это не панацея.

## Небольшие оговорки

- Поиск парсит HTML-страницу `https://author.today/search`. Если автор.today поменяет
  вёрстку - часть регулярных выражений придётся подправить.
- Результаты сортируются «по релевантности», поэтому между страниц списки могут
  «плавать» - скрипт собирает уникальные и честно сообщает о расхождении.
- Скрипт распространялся для персонального использования; не используйте в продакшене
  без регулировки лимитов.
